# Codex Context for Rant and Heal V2

This file serves as a high-level summary of the Rant and Heal V2 project. Review this before making architectural or deep codebase changes.

## 1. Tech Stack
- **Framework**: Next.js App Router (`/app`)
- **Backend/Auth**: Firebase (Auth, Firestore)
- **AI Integration**: OpenAI for Momo text/voice response delivery; Google Gemini for planning, safety classification, and other existing AI roles
- **Styling**: Tailwind CSS (Soft Clay Realism, following `stitch_rant_and_heal_ui/soft_clay_realism/DESIGN.md`)

## 2. Core Architecture
- **Identity Tier**: `users` collection in Firestore. Manages roles (`USER`, `THERAPIST`, `ADMIN`).
- **Professional Tier**: `therapists` collection. Public applicants submit `PENDING` profiles; only a Firebase Admin-custom-claim reviewer can make a profile `VERIFIED` and grant the `THERAPIST` role.
- **Relationship Tier**: `connections/{patientUid}` is a server-owned pointer to the current relationship. Immutable relationship history, messages, calls, signals, consent events, and call locks live under `therapy_relationships/{relationshipId}`. Therapists read only `patient_profiles/{patientUid}`, which excludes private account fields.
- **Service Layer**:
  - `src/services/`: Client-side Firebase helpers.
  - `src/server/`: Privileged Admin SDK integrations and server-only OpenAI/Gemini handlers.

## 3. Key Features & Locations
- **Momo AI Guide**: Server-owned chat history. Client calls `/api/momo/chat`, which validates bounded input, session ownership, quotas, idempotency, and per-session serialization. Each text session also has a bounded `continuityState` containing only interaction preferences, the active support goal/mode, brief user corrections, recent response metadata, and user-reported intervention outcomes; it excludes journals, therapy conversations, diagnosis, and model reasoning. This state informs planning and response validation but never overrides safety. Greeting-only turns may receive a sanitized first name from the authenticated profile, while incognito/placeholder profiles are treated as anonymous; this identity hint is not added to continuity memory. Cross-session personalization is not implemented. Text sessions now atomically persist a server-owned `safetyEvaluation` checkpoint so active risk is not lost when the 12-message history expires; existing transition rules advance once from that checkpoint. Firestore rules protect it. Failed ordinary generation preserves bounded explicit corrections/preferences. The 120-scenario synthetic quality audit and artifacts live in `tests/momo/conversation-corpus`; it is not clinical validation. Voice now creates an authenticated OpenAI Live WebRTC session through `/api/momo/live-session` and attaches a trusted server sideband before returning SDP. Browser-reported legacy Momo transcripts remain excluded from trusted history.
- **V4 Engineering Layer**: Provider-neutral contracts now live in `src/lib/momo`, `src/lib/safety`, `src/lib/reports`, and `src/lib/therapy`. Momo text follows safety evaluation → structured planner decision → server-only responder. The text responder defaults to OpenAI Responses (`gpt-5.6-luna`, medium reasoning, `store=false`) through `src/server/momo/textProvider.ts`; `MOMO_TEXT_PROVIDER=gemini` is the explicit rollback. Momo voice is pinned to OpenAI Live `gpt-live-1` and delegates substantive responses through the same safety → planner → Luna responder path. Other AI roles remain Gemini-backed, and there is no silent provider fallback. Model chain-of-thought is not requested or stored. `src/lib/ai/models.ts` owns model roles and thinking levels; `src/config/features.ts` owns server flags.
- **Momo Safety Interceptor v0.1**: Server-side assessment in `/api/momo/chat` and the Momo Live sideband. Non-normal safety states bypass ordinary support, use fixed policy copy, create an Admin-only `users/{uid}/safety_events/{eventId}` record, and expose interruption state to the authenticated browser. The voice sideband consumes incremental provider transcripts and sends same-session interruption instructions; a stale or disconnected monitor fails closed. This architecture still requires measured real-audio safety testing before release.
- **Trial flags**: `ENABLE_WEEKLY_REPORTS=true`, `ENABLE_AI_THERAPY_NOTES=true`, `ENABLE_SAFETY_DASHBOARD=true`, and `ENABLE_MOMO_VOICE=false` by default. Voice session creation and voice trial UI are disabled unless explicitly enabled; this must remain false until real-time safety interruption, barge-in, cleanup, truthfulness, and long-lived sideband deployment are verified.
- **Safety Support Notification**: Disabled-by-default, minimal Resend email alert after deterministic and structured-Gemini imminent-risk agreement. It contains no chat content or user identity. There is no emergency-contact storage, automatic calling, delayed dispatch, IP-location, or police workflow; the product must not claim live monitoring or emergency response.
- **Human Safety Dashboard**: `/safety` and `/safety/[caseId]` are protected by the explicit `safetyReviewer` custom claim (or existing admin claim). Day 3 review-required evaluations transactionally create/update session-bounded `safety_cases`; workflow status remains separate from clinical `SafetyState`. Server-only, idempotent mutations acknowledge, assign, record contact attempts/outcomes and verified handoffs, and resolve. Audit actions are append-only. Cases store only the triggering text and bounded assessment metadata—never journals, full transcripts, therapy history, or model reasoning.
- **Therapy MVP**: 
  - Patient routes: `/therapy` (find therapist, connection status), `/therapy/chat/[therapistId]` (chat room), `/therapy/session/[sessionId]` (video session).
  - Therapist routes: `/portal` (pending requests), `/patients` (roster), `/messages` (conversation threads), `/session/[sessionId]` (video session).
  - Calls are created and transitioned through authenticated route handlers. Sessions have explicit caller/recipient fields and expiring per-relationship leases; Firestore is used for participant-scoped WebRTC signals. Revocation ends the open call transactionally. Optional TURN configuration is released only to active participants with an unexpired session.
- **Shared UI shell**: Root layout owns the Daybreak canvas and responsive `GlobalSidebar` across public/auth, patient, and practitioner pages. Guests see Home/Crisis Support plus authentication actions. `useCurrentProfile` binds role lookups to the current UID; `useRequireRole` keeps workspace content behind role checks. `MoodTrend` plots the existing latest seven `health_metrics` entries, not a calendar week; mood/journal data remain owner-only.
- **UI Components**: Located in `src/components/` (divided into `ui/`, `forms/`, `shared/`, `layout/`).

## 4. Known Issues / Current Work
- **Momo conversation contract**: `src/lib/momo/prompts/conversationContract.ts` is the highest-level ordinary response policy. A 52-case synthetic library under `src/lib/momo/examples` selects 2–4 relevant principle sets only; dialogue, case facts, and backend statuses never enter live prompts. Shared explicit preferences now update continuity as well as planning. Bounded assertion checks cover unsupported emotions and work-credit overclaims; they are not full semantic validation. Native-speaker review of Nepali illustrations remains required. No safety/privacy schema changes are introduced by this policy layer.
- **Safety Protocol**: v0.1 is provisional keyword screening, not a clinical assessment. It needs Shubhangi/clinician-approved risk levels, localized response copy, a verified resource directory, escalation ownership, and English/Nepali/romanized Nepali evaluation cases before launch.
- **Safety Policy Layer**: Normalized state, schemas, response policy, and the Day 4 human-review operations foundation exist. A server-side Live transcript/interrupt path is implemented but not yet validated with real audio. Clinical closure/reopening policy, reviewer SLAs/coverage, legal retention/disclosure approval, and measured voice-safety latency remain incomplete.
- **Therapy deployment**: Run `npm run migrate:therapy` as a dry run, review it, then run it with `-- --apply` before deploying the new rules. Deploy `firestore.indexes.json` with the rules. TURN configuration and two-browser testing across real networks remain launch requirements.
