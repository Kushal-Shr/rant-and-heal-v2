# Codex Context for Rant and Heal V2

This file serves as a high-level summary of the Rant and Heal V2 project. Review this before making architectural or deep codebase changes.

## 1. Tech Stack
- **Framework**: Next.js App Router (`/app`)
- **Backend/Auth**: Firebase (Auth, Firestore)
- **AI Integration**: Google Gemini (via `@google/genai`)
- **Styling**: Tailwind CSS (Soft Clay Realism, following `stitch_rant_and_heal_ui/soft_clay_realism/DESIGN.md`)

## 2. Core Architecture
- **Identity Tier**: `users` collection in Firestore. Manages roles (`USER`, `THERAPIST`, `ADMIN`).
- **Professional Tier**: `therapists` collection. Public applicants submit `PENDING` profiles; only a Firebase Admin-custom-claim reviewer can make a profile `VERIFIED` and grant the `THERAPIST` role.
- **Relationship Tier**: `connections/{patientUid}` is a server-owned pointer to the current relationship. Immutable relationship history, messages, calls, signals, consent events, and call locks live under `therapy_relationships/{relationshipId}`. Therapists read only `patient_profiles/{patientUid}`, which excludes private account fields.
- **Service Layer**:
  - `src/services/`: Client-side Firebase helpers.
  - `src/server/`: Privileged Admin SDK integrations and Gemini handlers.

## 3. Key Features & Locations
- **Momo AI Guide**: Server-owned chat history. Client calls `/api/momo/chat`, which validates bounded input, session ownership, quotas, idempotency, and per-session serialization. Voice uses a persisted session and `/api/momo/live-token`; transcript routes mark browser-reported model text as untrusted provenance.
- **Momo Safety Interceptor v0.1**: Server-side phrase screen in `/api/momo/chat` and `/api/momo/transcript`. High-confidence direct self-harm or harm-to-others signals bypass Gemini, save fixed support copy, create an Admin-only `users/{uid}/safety_events/{eventId}` record, and route the client to `/crisis`. Text is protected pre-generation; voice is only protected after a completed transcript, not in real time.
- **Safety Support Notification**: Disabled-by-default, minimal Resend email alert after deterministic and structured-Gemini imminent-risk agreement. It contains no chat content or user identity. There is no emergency-contact storage, automatic calling, delayed dispatch, IP-location, or police workflow; the product must not claim live monitoring or emergency response.
- **Therapy MVP**: 
  - Patient routes: `/therapy` (find therapist, connection status), `/therapy/chat/[therapistId]` (chat room), `/therapy/session/[sessionId]` (video session).
  - Therapist routes: `/portal` (pending requests), `/patients` (roster), `/messages` (conversation threads), `/session/[sessionId]` (video session).
  - Calls are created and transitioned through authenticated route handlers. Sessions have explicit caller/recipient fields and expiring per-relationship leases; Firestore is used for participant-scoped WebRTC signals. Revocation ends the open call transactionally. Optional TURN configuration is released only to active participants with an unexpired session.
- **Shared UI shell**: Root layout owns the Daybreak canvas and responsive `GlobalSidebar` across public/auth, patient, and practitioner pages. Guests see Home/Crisis Support plus authentication actions. `useCurrentProfile` binds role lookups to the current UID; `useRequireRole` keeps workspace content behind role checks. `MoodTrend` plots the existing latest seven `health_metrics` entries, not a calendar week; mood/journal data remain owner-only.
- **UI Components**: Located in `src/components/` (divided into `ui/`, `forms/`, `shared/`, `layout/`).

## 4. Known Issues / Current Work
- **Safety Protocol**: v0.1 is provisional keyword screening, not a clinical assessment. It needs Shubhangi/clinician-approved risk levels, localized response copy, a verified resource directory, escalation ownership, and English/Nepali/romanized Nepali evaluation cases before launch.
- **Therapy deployment**: Run `npm run migrate:therapy` as a dry run, review it, then run it with `-- --apply` before deploying the new rules. Deploy `firestore.indexes.json` with the rules. TURN configuration and two-browser testing across real networks remain launch requirements.
